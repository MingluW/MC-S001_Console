# 按键与LCD显示演示

日期：2026-10-28。用于验证按键输入、数字段码和非阻塞刷新。
这是显示演示，不向下控发送电机命令；0.0~30.0为暂定演示范围，不是产品规格。

## 板上操作（当前版本）

1. 屏幕初始化后全亮0.5s，然后四位数字依次3333→2222→1111→0000，每步0.5s。
2. 进入等待，8888每1s亮灭切换；此时加减无效，等待K801开始键。
3. 按开始后坡度归0，显示GRADE和整数0；停留0.5s后切速度0.0（默认KPH）。
4. 运行界面按坡度加减即切坡度并调档，保持坡度页；按速度加减切速度并调值，保持速度页。
5. 任意阶段按K806停止，直接转为----；停止时加减无效。再次开始，重复坡度0→0.5s→速度0.0。

- 六键低有效：K801开始PB10、K802坡度减PB11、K803坡度加PB12、K804速度减PB13、
  K805速度加PB14、K806停止PB15。
- 速度范围0.0~30.0，步长0.1；坡度暂定整数0~15，步长1。均为演示参数，不代表产品规格。
- 加减键按住500ms后每100ms连调，达到边界保持；同组加减同时稳定按下时不调整。
  开始/停止只有按下事件，不连发；开始仅在等待或停止状态有效。
- 开机动画期间开始/加减无效；启动坡度0的0.5s停留期间加减无效，停止始终可打断。
- 上电已按住的键需先释放，再按才触发。每10ms采样、20ms稳定确认，主循环不等待。
- 全亮、倒计时、等待闪烁、启动坡度停留，均从对应完整帧发送完成后计时，避免LCD初始化跳过动画。
- 停止绕过显示50ms合并间隔，保留正常20ms按键消抖；正在发送的帧先完成，再输出----。
- 蓝灯继续亮灭各1500ms；回显和周期自测日志保持关闭。本版无CAN、下控或实际电机控制。

检查顺序：开机完整动画→8888明灭→开始→GRADE 0→0.5s后KPH 0.0→坡度加减→
停留坡度页数秒→速度加减切回→停止----→再次开始；另检查动画/启动停留中停止、断电重启。
屏幕显示、其余四键输入及新流程均待本版实板确认。

## 代码阅读顺序

```text
BoardKeys_Read          将PB10~PB15低电平转换成六键按下位图
Keys_Process            消抖、产生PRESS/REPEAT事件，不知道速度和LCD
AppControl_Process      优先停止，处理事件与界面计时，统一修改AppState
AppDisplay_Process      按状态构帧；切页立即提交，同页参数变化最多每50ms一次
Lcd_Process             初始化等待/逐字发送，每次最多一个9位字
```

- 源码分别位于USER/src/Board、USER/src/Modules/keys、USER/src/App和Modules/lcd。
  新头文件仍集中放在USER/inc，Makefile显式添加keys目录；VS Code原有USER/inc路径已覆盖。
- Board手工初始化六路输入为上拉，依据原理图K801~K806按下接地。
- Keys_Process只负责10ms采样和逐键调度：先调用私有debounce_process确认状态，
  再调用repeat_process处理长按连发。消抖与连发分开阅读，参数与原有行为保持一致。
- Keys的8条普通事件队列满时丢新并累计，App通过WARN报告；停止使用独立锁存位，
  不受普通队列满影响，优先取出并清除此前普通事件。同轮开始/加减不能覆盖停止。
- AppState中的demo_speed_x10是显示值的10倍，例如125表示12.5；不表示下控反馈。
- 旧Cypress的Tube1~Tube4每位0~9、横杠、point3、GRADE及速度单位段码以const表复用，旧工程保持只读。
  段码层最多表达999.9；应用单独限制30.0。全程整数运算，不引入浮点格式化。
- AppDisplay逐帧比较16字节内容，同页50ms内多次改变合并为最新状态；切页立即提交。
  Lcd_SetFrame立即复制16字节，不保留调用方指针；初始化期间可预提交。
- Lcd内部继续使用发送快照，中途改目标留到下一帧，避免一帧混入不同数值。
  一帧为4个头字+16个数据字，分20次Process完成；软件测试未测实板CPU耗时。
- Lcd_SetFrame失败不更新AppDisplay的已提交状态；不自动重试硬件初始化。
  显式重新初始化LCD时同时调用AppDisplay_Init，确保恢复后重新提交状态。

## 可选速度单位

- `USER/inc/app_control.h`中的`APP_DEFAULT_SPEED_UNIT`默认是`APP_SPEED_UNIT_KPH`。
- 主循环中调用`AppControl_SetSpeedUnit(APP_SPEED_UNIT_MPH)`或
  `AppControl_SetSpeedUnit(APP_SPEED_UNIT_KPH)`选择单位；返回false表示无效参数。
  当前未指定单位切换按键，不添加临时按键组合，不写入Flash；重启使用默认值。
- 单位属于AppState，AppDisplay同时比较数值与单位；只改单位也会在刷新间隔到期后提交。
- 当前显示演示切换单位只改标识，保留演示数值；尚未接入真实速度，不实施英制/公制换算。
  接入真实速度时需明确内部统一单位、换算和限值规则。
- 旧逐段表Lcd_code说明第13字节的低4位：速度图标0x01、PH共用0x02、M为0x04、K为0x08。
  KPH使用0x0B，MPH使用0x07（均包含速度图标）；不再用全开0x0F作为正常速度单位。
  高4位仍归数字段码，构帧时通过按位或合并，不覆盖数字。
- 两种单位的段码、默认KPH、运行时选择、无效参数及仅改单位刷新已通过ARM软件测试。
  单位拆分版尚未烧写，KPH/MPH的实际显示待验证；此前正常显示和加减的实板结论属于旧版本。


## 界面状态与后续CAN

界面状态集中在AppScreen：BOOT_ALL、BOOT_COUNTDOWN、WAIT_START、START_INCLINE、SPEED、INCLINE、STOPPED。
AppControl_Process接收毫秒时间和最新目标帧是否发送完成；App只装配，不在LCD里处理按键或控制状态。
APP_BOOT_STEP_MS=500、APP_WAIT_BLINK_MS=1000、APP_START_INCLINE_MS=500集中在app_control.h。
CAN后接入时沿用AppControl作为统一动作入口，将目标值、实际反馈、请求/确认和通信故障分开定义；
不能把本版演示状态的变化视为电机已经执行。现阶段不建立空通信模块。
