# CAN发送超时排查与RX配置修复

日期：2026-10-29。用户已运行首版CAN固件并提供串口日志。

用户随后明确：截图测试时没有连接下控。以下寄存器快照均是在这个条件下取得。
无其他应答节点时，不能期待CAN硬件ACK、TX_SENT或FP2响应；缺少这些现象本身不证明程序异常。
此前把“下载后应出现TX_SENT”作为不加前提的判断不准确，需要对端或内部回环条件。

## 实板观察

开始后写301=0.3 KPH，出现TX_REQ；200ms后TX_TIMEOUT，随后取消完成并TX_FAIL。
未看到TX_SENT、CAN RX或FP2应答。之后误继续提交订阅，也出现同样发送失败。
日志状态TEC=0、REC=0、LEC=7、DLEC=1792，不足以认定为对端未ACK。

通过J-Link只读寄存器（未执行r/h/g、未烧写、未写寄存器）获得：

```text
FDCAN1 CCCR  0x40005018 = 00000340
FDCAN1 NBTP  0x4000501C = 26008A13
FDCAN1 ECR   0x40005040 = 00000000
FDCAN1 PSR   0x40005044 = 00000707
FDCAN1 TXBRP 0x400050CC = 00000000
FDCAN1 TXBTO 0x400050D8 = 00000000
FDCAN1 TXBCF 0x400050DC = 00000001
RCC CFG3     0x4002100C = 60300075
GPIOB PMODE  0x4002C400 = 000FF49F
GPIOB AFSEL0 0x4002C40C = 1A000000
GPIOB PID    0x4002C42C = 0000FC34
```

CCCR.INIT=0，已退出初始化；PSR.ACT=0为同步状态。
PB3的PMODE位[7:6]=2，为复用输出，AF=26；PID采样PB3=0。
TX已取消，不能把TX_REQ当作实际完成；TEC/REC无错误计数与未获得空闲状态的现象相符。
以上是一次运行中读取快照，不是示波器波形，也不能单凭它排除线路或收发器问题。

## 代码修复

1. BoardCan_Init为TX选AF_PP后，RX原先没有重新设置GPIO_Mode，错误沿用了复用输出。
   改PB3为GPIO_MODE_INPUT，保留上拉与FDCAN1_RX/AF26，避免输出模式与外部收发器RXD争用。
   SDK头文件明确GPIO_MODE_AF_PP是GPIO_PMODE_AF_OUTPUT，输入方向需单独指定。
2. SDK FDCAN_GetProtocolStatus返回LastDataError为PSR掩码，未右移。
   1792即0x700，解码为DLEC=7，表示自上次读后无新错误；修复为右移8位后记录。
3. 增加RX电平、ACT与CCCR诊断到TX_FAIL和CAN STATUS，ACT解码为0同步/1空闲/2接收/3发送。
4. 首次速度事务失败时清除待发订阅，避免基础发送失败后继续发额外请求。

本次没有更改速率、节点ID、速度编码、心跳策略或启停UI行为。
