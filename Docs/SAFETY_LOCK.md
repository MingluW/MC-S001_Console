# 安全锁：检测、停速、警示和接回

日期：2026-11-10。已编码、GCC构建及ARM ELF软件验证通过；本轮未烧写、未实板验证。

## 硬件与初始化

依据上控原理图（B756Y V1.0，2026-09-24）INTERFACE及MCU页：
CN302安全锁输入经R323/R322与U301两级反相后，DMK接PA9（31脚），高为断开。
PB6（43脚）SAFEKEY_EN是输出，经过U303 NOR逻辑及Q302/MQ301控制SAFEKEY_R；
PB6高为软件禁止，低仅解除软件禁止，物理安全锁DMK仍参与硬件门控。
以上为原理图分析，实板电平和下控行为仍待确认。

BoardSafety_Init手工配置PA9上拉输入、PB6无上下拉推挽输出；先预置PB6高，再切输出模式。
该配置位于Board，不改N32Cube生成代码，不启用EXTI。App_Init最先初始化安全锁，
AppControl初始化后读原始电平，决定保持禁止或解除软件禁止。
board_safety.c由Makefile既有Board目录通配符纳入；手写头文件在USER/inc，VS Code现有路径已覆盖。

## 运行行为

- 每轮App_Process在按键及CAN请求前读PA9。高电平立即触发，不延迟断开保护。
- 目标速度清零、进入停止状态、取消通信速度预览；PB6保持高。
- Powerboard_SetSafetyLock禁止START/速度API，清待发速度和订阅，优先请求301=0。
- 已发到硬件的旧帧不能保证撤回；等待完成/取消确认后才复用缓冲提交零速度。
- 零速度失败仍沿用500ms非阻塞重试；重复检测到锁断开不取消本次STOP、不重置重试计时。
- 常亮显示5AFE（首位数字5近似S），使用原Cypress的5/A/F/E段码，无单位、小数点或图标；不闪烁。
- 安全锁警示优先于普通故障、E-01和所有普通页。故障接收/首因锁存继续执行。
- 持续采样、消抖并消费全部键事件，START/加减不执行，STOP保持停止且不改变5AFE警示。
- CAN收发、应答/超时、LCD刷新、UART日志、1500ms蓝灯均继续调度。没有等待接回的while循环。

接回低电平连续100ms才解除警示；任一高电平打断接回计时。保持目标0和停止状态，
不重播开机动画、不恢复旧速度。若有既有错误，恢复相应错误显示；普通故障不被清除。
接回后所有键的原始及消抖状态均释放，并稳定30ms，才接受新操作；期间事件全部消费，
须再次按START，按现有0.3 KPH启动流程运行。已锁存普通故障时仍不能启动。

CAN提交、TX_SENT或ACK均不代表真实电机已停止；硬件线路、实际制动和停转时间需实板确认。
不增加心跳，不改TEST或Cypress参考工程。

## 软件验证

Tests/test_safety_lock.py执行实际Console ARM ELF，包含test_fault_policy.py及CAN回归：
SDK PA9/PB6方向与有效电平、PB6先预置禁止；运行中旧速度发送/队列抢占、
未确认取消时不复用缓冲、STOP失败500ms重试、ACK不解除物理锁；
5AFE逐段对照旧表、LCD忙/长时间停留时常亮且不重复提交、接回100ms边界/抖动、按住START/释放30ms；
故障期间接收并保留首因、上电缺锁、uint32计时回绕、真实App_Process调度接入。
Tests/test_ui_flow.py通过原有按键、LCD底层、启动/停止/切页及单位回归。
软件替身不模拟真实GPIO电气、NVIC、CAN电气和下控电机执行。

## 待实板操作

1. 确认J-Link连接Console。经用户明确要求烧写后再下载本版。
2. 安全锁正常接入上电，核对启动界面和按键；缺锁上电应直接显示5AFE且保持停速。
3. 运行中断开，观察5AFE常亮；核对日志零速度请求、下控反馈和实际电机停转。
4. 断开时按START/加减/STOP不应恢复运行或改变警示；通信断开时仍应显示5AFE、蓝灯运行、STOP重试。
5. 接回后应停止且不恢复旧速度；接回时按住START，释放后重新按下才能启动。
6. 已锁存普通故障时拔插安全锁，警示退出后仍显示首个故障，START/加减无效。
7. 实测PA9断开/接回电平、PB6禁止电平及SAFEKEY_R动作，并记录真实停转结果。
